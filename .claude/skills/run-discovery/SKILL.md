# /run-discovery — Validate before building

## When to use
Before committing build effort to a new idea, feature, or initiative; to validate a problem/solution or
understand users.

## Dispatches
`discovery-researcher` (lead). Hand validated learnings to `product-manager` for PRD/prioritization.

## Inputs
`knowledge/product-context.md` (target customer, problem), `knowledge/roadmap.md`.

## Steps
1. Identify the riskiest assumption (value / usability / feasibility / viability); attack it first.
2. Frame falsifiable hypotheses with pre-stated success thresholds.
3. Design the cheapest test that yields a real signal (interview guide, prototype test, fake-door, data).
4. Synthesize into jobs/outcomes, personas, and an opportunity view — not feature lists.
5. State validation strength honestly and recommend persevere / iterate / pivot.

## Methods
`knowledge/methods/discovery-and-validation.md`, `knowledge/methods/lean-product-process.md`.

## Output
Discovery artifact (research plan, synthesized findings, personas — use `templates/persona.md` —, validated
learnings); reflect key
learnings into `knowledge/product-context.md`; log validation decisions to `knowledge/decision-log.md`.
Follow `standards/document-standards.md`.
